Computer use that feels instant, for any agent on your Mac

An MCP server and CLI that any coding agent can call to see and drive Mac apps in the background. It aims to beat every current tool on the one test that matters: getting the job done while you keep working, in the fewest model calls, cheap enough to run on Haiku.

03 · Where the time and money go

Round trips and the fixed prompt cost the most; the Mac itself is fast

I measured the Mac side on this machine (M4 Pro, macOS 27.2.1) today. Every local operation takes tens of milliseconds or less. A model round trip takes seconds. The tool wins by needing fewer, smaller model calls, and by never answering before the app has finished updating.

04 · The bets

Table stakes we must match, and where we can win

Since October the field has converged. Cua added batching, change summaries and a script runner (0.35, 12 Oct). Microsoft open-sourced HCU (30 Oct). Aside, agent-desktop and Peekaboo all ship compact Accessibility snapshots and background input. Matching that is the entry ticket. The wins are in the last three cards.

table stakes

Compact outline, then only the changes

Focused window only, short stable IDs, noise dropped. After the first look, send only what changed. Byte-stable output so prompt caching works.

agent-desktop skeleton: 273 vs 3,811 tokens 31 Oct
Blindsight outline: 322/330 vs 317 for screenshots, ⅓ the tokens 22 Oct
table stakes

Batches that stop on failure

One call carries several steps and waits, stops at the first failure, and returns one change summary.

HCU: up to 64 actions per call, −30% steps 30 Oct
Astra batched: 127 s vs 183 s, same score 30 Sep
table stakes

The tool picks the route

Use the app's scripting dictionary where it has one, then an Accessibility action, then a background pixel click. Keep the guide tiny: script channels raise cost when they come with long instructions.

MacAgentBench: 39% → 74% pass, but $0.98 → $1.35 per task 20 Oct
beans-picker over Cua: 28 s vs 50 s, $0.06 vs $0.39 27 Sep
differentiator

Never touch the user's input

Send events only to the target app, never take focus or move the real cursor, pause while you type. Background pass rate with a typing user is where tools differ most: 95%, 45% and 25% with the same model.

Codex: doubled keystrokes still open (#50728, #61326) 13 Nov
Claude Code CLI: still no background mode (2.1.323) 12 Nov
differentiator

Answer the moment the app is ready

The live UI copy exists for this. Accessibility change notifications say exactly when the UI settled, so each action returns as soon as it's safe and never early. Reading speed isn't the reason: a full walk already takes under 85 ms here.

fixed waits: 42% of interaction time, 63% of it after the screen was ready 28 Oct
a simple pixel check matched a frontier model at ⅛ the latency 29 Oct
differentiator

Make Haiku good enough

A better tool makes a cheaper model viable. Haiku 5.5 costs $0.10 / $0.50 per million tokens against $4 / $20 for Opus 5.5. If Haiku passes most tasks, cost per task drops by an order of magnitude.

Haiku 5.5 on Aside: 92% foreground, $1.21 per 90 trials vs $25.67 for Opus 12 Nov

Later, not Sunday: replaying routines that already worked. EchoPath cut median tokens by over 90% and time by about 60% 15 Sep, but PACE found a compiled routine pays off only after 2 to 16 uses once failures are counted 2 Oct.

05 · Architecture

A long-running daemon, with thin MCP and CLI front ends

The daemon holds all the state: mirrors, permissions, recent changes. The MCP server and CLI are thin clients, so both start instantly and see the same apps. AppleScript runs compiled inside the daemon, so there's no 67 ms osascript start per call.

06 · What the agent sees

07 · Tool surface

Seven tools, and nothing else

Tool definitions are the biggest fixed cost now. agent-desktop's fixed prefix is about 12.8k tokens, 34 to 68% of all its input 11 Oct; Anthropic's computer toolset adds about 4,500 per request. Changing a tool definition also throws away the whole prompt cache. So the schema stays under 1,500 tokens and never changes mid-session. Each tool is also a CLI verb with the same arguments.

apps(query?)

Find apps, running or installed, through LaunchServices and Spotlight. This is how the agent finds your video editor without being told its name.

observe(app, window?)

The outline of the focused window. Later calls return only what changed since the last look, or "no change".

act(app, steps[], until?)

The main tool. Steps: click id, set id value, type, key, scroll, menu path, wait condition. It runs them through the router, waits for the UI to settle after each one, stops at the first failure and returns the change summary.

script(app, source, lang?)

AppleScript or JXA, compiled and run inside the daemon, for apps with a scripting dictionary. Result as text.

see(app, region?, zoom?)

A screenshot of one window at 960×540, or a zoomed crop. Only for what the outline can't show: canvases, video frames, charts.

timeline(app, events[])stretch

Key and mouse events on a precise schedule, run locally with millisecond timing. The agent plans once and the daemon plays it. This powers the piano test.

routine(name, params?)later

Save the last successful act batch as a named routine, or run a saved one. Falls back to the agent if a step no longer matches.

09 · Benchmarks

Run the shared benchmark first, then our own three tiers

Every setup runs under the same agent, model and prompt; only the computer use tool changes. Baselines, all free under Claude Code: the built-in tool, Cua Driver, agent-desktop, Peekaboo and HCU. Aside Computer Use is in Scale's data already. Codex in its own app with GPT models needs one month of ChatGPT Plus ($20).

Tier 0

Cua Driver Bench v2

  • 10 tasks: multi-app workflows, precision clicks, interruptions
  • Foreground and background with a simulated typing user
  • Runs through claude -p; already in the reference folder

Pass: its own checkers. Our numbers line up directly with Scale's published rows. It assumes macOS 26 and Cua used macOS 26 VMs, so check it runs on 27.2.1.

Tier 1

Everyday tasks

  1. Change a System Settings toggle, then put it back
  2. Write a note in Notes and file it in a folder
  3. Fill a native form and save through a save prompt
  4. Rename and move files in Finder
  5. Make a calendar event from details in a Mail message

Pass: state checked by script after each run. Win on median time, calls and tokens.

Tier 2

Edit a video, start to finish

  • Find the editor installed on the Mac, with no name given
  • Learn its interface from menus, help and the outline
  • Cut three given clips, add a title and music, export 1080p

Pass: the exported file exists, is 1080p, has the right length and the title frame. Timelines are drawn by the app itself, so this tests the screenshot fallback.

Tier 3

Play the Moonlight Sonata

  • Find a public-domain MIDI of movement 1
  • Open an online piano and work out its key mapping
  • Compile the piece to a timed event list, play it via timeline

Pass: record the audio and compare note onsets to the MIDI. Target: median error under 20 ms. Movement 3 is the follow-up.

10 · Risks and open questions

What could sink it, and what to check first

high

The field moves weekly

Cua shipped about 60 releases since 5 Nov. Aside launched 6 Nov and leads the benchmark. Most of our ideas are already shipping somewhere. The pitch has to be a measured result on the shared benchmark, not the architecture.

high

Background input depends on private APIs

Clicking without raising a window takes SkyLight calls Apple doesn't document. Cua added background clicks for macOS 27 only on 5 Nov. Read how Cua, Peekaboo and open-computer-use do it first, and keep Accessibility actions as the default route.

high

Apps that draw their own UI

Video timelines, canvases and games expose almost no Accessibility tree. Local grounding models are still slow on Apple Silicon: 8 to 35 s per step in Aug to Oct reports. Sunday covers only see plus coordinates.

medium

Raw trees lose to screenshots

Microsoft's Mage-VL study found adding a raw AX channel cut success from 92.0% to 89.6% and added 10 steps 29 Oct. Only a compact outline helps, so measure outline tokens from the first day.

medium

Piano timing and polyphony

Some web pianos can't play several notes at once, and background tabs may throttle input. Check the site by hand on Saturday.

low

Permissions friction

Needs Accessibility, Screen Recording and Apple Events. Doorman's onboarding already handles the first two.
